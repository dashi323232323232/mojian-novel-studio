# 大师小说工作台

> 简洁、现代、本地优先的 Windows 长篇小说创作工作台。
> 项目管理 · 阶段章节 · 图形化大纲 · 大纲正文联动 · 伏笔追踪 · 有声小说 · 本地 Agent API · 多实例（默认密码 Qy123456）

**软件版本**：1.5.0 ｜ **API 版本**：v1 ｜ **平台**：Windows 10/11 x64

---

## 一、快速开始

### 方式 A：直接使用打包版（推荐）

1. 双击桌面快捷方式 **「大师小说工作台」**，或运行：
   ```
   dist-packaged\DashiNovelStudio-win32-x64\大师小说工作台.exe
   ```
2. 首次启动会自动创建本地数据库，无需安装任何额外运行时。

> 若桌面快捷方式丢失，可重新创建：
> ```powershell
> powershell -NoProfile -ExecutionPolicy Bypass -File scripts/create-shortcut.ps1
> ```

### 方式 B：从源码运行（开发）

环境要求：Node.js ≥ 22.12（推荐 24.x）、Windows 10/11。

```bash
npm install          # 安装依赖（Electron 二进制较大）
npm run build        # 构建主进程 + 渲染层
npm start            # 启动桌面应用
```

开发模式（热更新）：

```bash
npm run dev          # 同时启动 Vite 与 Electron
```

重新打包：

```bash
npm run package      # 输出到 dist-packaged/DashiNovelStudio-win32-x64
```

> 若 Electron 二进制下载失败，可设置镜像：
> ```powershell
> $env:ELECTRON_MIRROR="https://npmmirror.com/mirrors/electron/"
> npm install
> ```

### 大纲节点的语义（重要）

很多 AI 只会用「故事阶段」和「具体章节」，导致大纲只剩骨架、缺少情节。正确的用法是三层结构：

| 类型 | 时间尺度 | 例子 | 作用 |
| --- | --- | --- | --- |
| `stage` 故事阶段 | 几个月 ~ 几年（长期） | 「我的高中三年」 | 大时间段，是"盒子" |
| `event` 剧情事件 | 几小时 ~ 几天（短） | 「和同桌打了一架」 | 盒子里的一件具体小事 |
| `chapter` 具体章节 | 一个叙事单元 | 「第三章 梁子结下了」 | 真正写正文的地方 |
| `foreshadow` 伏笔 | 跨多个事件/章节 | 「军旗第 1 章埋下、第 12 章回收」 | 隔很久才回收的线索 |

推荐结构：

```
故事阶段（高中三年）
  │ contains 包含
  ├── 剧情事件（和同桌打了一架）
  │       └── 关联章节 → 第三章
  ├── 剧情事件（第一次月考失利）
  │       └── 关联章节 → 第五章、第六章   ← 一个事件可写多章
  └── 剧情事件（运动会接力赛）
          └── 关联章节 → 第七章
```

- 事件用 `contains` 连到阶段（不要用 `sequence`）；
- 一个事件可以关联多个章节，不要复制多个事件节点；
- 跨很多章才回收的线索用伏笔，不要用事件表达。

完整的字段说明、判断清单、6 步调用示例见：

- [docs/OUTLINE_GUIDE.md](docs/OUTLINE_GUIDE.md) —— **独立的大纲使用说明**，推荐单独复制给只关心大纲搭建的 AI；
- [docs/AGENT_GUIDE.md](docs/AGENT_GUIDE.md) 的「3.5 大纲节点」章节 —— 完整接口文档中的对应部分。

软件「Agent 接入」页也提供 **「复制大纲使用说明」** 按钮，一键复制全文（含真实令牌与当前服务地址）。

### 卷册分级目录

内容页的章节目录改成文件管理器式的**三级结构**：

```
第 1 卷 · 第一卷 风起        ← 卷（阶段），可收缩
  ├── 第 1–20 章            ← 分组框，每 20 章一个，可收缩
  │     ├── 第一章 宣战
  │     ├── 第二章 ...
  │     └── 第二十章 ...
  └── 第 21–40 章
第 2 卷 · 第二卷 ...
```

| 规则 | 说明 |
| --- | --- |
| 卷标题 | 形如「第 1 卷 · 第一卷 风起」，卷序号由阶段顺序自动生成 |
| 分组标题 | 形如「第 1–20 章」「第 21–40 章」，**每 20 章一个分组框**（常量 `CHAPTERS_PER_GROUP = 20`） |
| 默认状态 | **全部收缩**：卷是收起的；展开某个卷后，里面的分组框**仍然是收缩的**，需要再点一次展开 |
| 返回自动展开 | 从编辑页返回目录时，会**自动展开刚才那一章所在的卷与分组**，不用再手动找 |
| 章节下拉 | 音频页的章节下拉同样按卷分组 |

> 目录树由 `src/lib/chapterTree.ts` 纯函数构建（空数组、20 的整数倍、章节乱序输入都能正确处理，且不修改入参），渲染组件为 `src/components/ChapterTree.tsx`。

### 大纲自动排版

大纲页工具栏新增 **「自动排版」** 按钮，用于把手工摆得七零八落的节点重新整理成可读的版式。弹窗左侧调参数、右侧**实时预览**，并给出「布局质量对比」。

**4 种布局风格**

| 风格 | 适用场景 |
| --- | --- |
| 分层流程 | 按剧情先后分层、同层并排，最清晰，适合主线与伏笔穿插 |
| 环形辐射 | 以连接最多的节点为中心，其余按关系远近向外展开 |
| 类型分组 | 阶段、事件、章节、人物、伏笔各自成块，块内再分层 |
| 紧凑排布 | 优先缩小整体面积，节点多、画布大时更省空间 |

**参数说明**

| 参数 | 取值 | 说明 |
| --- | --- | --- |
| 主方向 | 从上到下 / 从左到右 | 分层、分组、紧凑布局的展开方向；环形布局不使用 |
| 同层对齐 | 居中 / 左·上对齐 | 同一层节点在交叉轴上的对齐方式；环形布局不使用 |
| 水平间距 | 40 ~ 400px，步长 10 | 同层节点之间的横向留白 |
| 垂直间距 | 40 ~ 400px，步长 10 | 层与层之间的纵向留白 |
| 层内排序 | 按节点类型 / 按标题 / 按连接数 | 只决定初始顺序，算法会在此基础上继续微调以少交叉；环形布局不使用 |
| 按类型分组 | 开 / 关 | 把同类型节点放到一起；「类型分组」风格已默认分组 |

**质量对比**（应用前 vs 应用后）

| 指标 | 含义 |
| --- | --- |
| 连线交叉 | 两条连线在画面上相交的次数，越少越清晰 |
| 重叠节点 | 节点矩形互相压住的数量，理想为 0 |
| 连线总长度 | 所有连线端点距离之和，越短越紧凑 |

- **应用前自动备份原位置**，工具栏的 **「撤销排版」**（弹窗内的「恢复原来的位置」）可一键还原；切换项目会清掉旧备份，避免把 A 项目的坐标用到 B 项目。
- **兼容性**：排版**只更新节点已有的 `x` / `y`**，不新增任何数据字段、不改动节点内容与连线，因此**完全兼容旧数据**；旧项目打开后直接可用。

## 四、多实例与密码保护

### 4.1 同时运行多个实例

右上角窗口控制按钮（最小化 / 最大化 / 关闭）的左侧有一个 **「新建实例」** 按钮（两个方块重叠的图标）。点击后输入密码即可再启动一个独立实例，两个窗口可以同时使用、互不影响。

| 项目 | 说明 |
| --- | --- |
| 独立窗口 | 每个实例是一个独立进程，有独立窗口与托盘图标，窗口标题带实例名（例如「大师小说工作台 · 第二部小说」），便于区分 |
| 独立数据 | 每个实例使用独立的 `userData` 目录 `<主实例 userData>/instances/<实例 id>/`，因此数据库（`dashi.db`）、音频、备份、界面设置**全部独立** |
| 实例清单 | 所有实例的元信息记录在主实例 `userData` 下的 `instances.json`：`{ "instances": [{ "id", "name", "createdAt", "lastOpenedAt" }] }` |
| 主实例 | 不带 `--instance` 参数启动的进程是主实例（id 固定为 `main`），仍保留原有的单实例锁语义；带 `--instance=<id>` 启动的子实例会跳过单实例锁 |
| 程序文件 | 所有实例**共用同一份程序文件**（同一 exe / 同一套 `resources`），只有 `userData` 与数据库是隔离的 |
| 启动方式 | 子实例由主实例用 `child_process.spawn(process.execPath, [...args, --instance=<id>])` 以 detached 方式拉起。**打包版**直接是应用 exe 加参数；**开发模式**是 `electron.exe` 加项目根目录再加参数，两种拼法在 `electron/main/index.ts` 的 `buildInstanceArgs()` 里分别处理并有注释 |

> 多实例同样适用于开发调试：也可以手动执行 `electron . --instance=inst_test` 验证数据隔离。

### 4.2 密码保护

- **默认密码**：`Qy123456`。首次点「新建实例」时输入该密码即可，**首次使用后请尽快修改**。
- 密码用于**新建实例的校验**，不会上传到任何服务器，也不会写入 Git 仓库。
- **存储方式**：只在本机数据库 `app_settings` 表的 `instance.auth` 键里保存 **scrypt 加盐哈希**：

  ```json
  {
    "algo": "scrypt",
    "salt": "<随机 16 字节盐的 hex>",
    "hash": "<scrypt 派生结果的 hex>",
    "iterations": 16384,
    "updatedAt": "<ISO 时间>",
    "isDefault": true
  }
  ```

  **不保存明文密码**；每次初始化都用 `crypto.randomBytes` 生成新盐，因此两个实例即使使用同一个密码，盐与哈希也不同。校验使用 `crypto.timingSafeEqual` 做恒定时间比较。

- **修改密码**：在「新建实例」弹窗内可修改（当前密码正确才能改），新密码至少 4 个字符、最多 1KB；修改后旧密码立即失效。仍在使用默认密码时，弹窗会给出「建议尽快修改」的提示。
- **安全边界**：密码保护的是「新建实例」这一动作，属于本机使用的便捷锁，不是磁盘加密；持有本机数据目录的人仍可直接读取数据库文件。

## 五、数据保存位置

默认用户数据目录（Electron `userData`），**可在「设置与备份 → 数据存储位置」中更改**：

```
%APPDATA%\大师小说工作台\
├── dashi.db              # SQLite 主数据库（WAL 模式）
├── dashi.db-wal / -shm   # WAL 日志
├── api-endpoint.json     # 本地 API 服务发现文件（不含令牌）
├── audio\<projectId>\    # 离线音频生成的文件（实时朗读不产生任何文件）
└── backups\              # 自动 / 手动备份（保留最近 20 份）
```

可通过「设置与备份 → 打开数据目录」直接定位。

> 多实例：主实例仍使用上面的默认目录，新建的实例各自使用 `<主实例目录>/instances/<实例 id>/` 作为 `userData`，因此每个实例都有自己的 `dashi.db`、`audio/`、`backups/` 与 `data-location.json`，互不覆盖。实例清单位于主实例目录下的 `instances.json`。

**更改数据存储位置**：

1. 打开「设置与备份 → 数据存储位置」；
2. 点击「选择新位置并迁移数据」，选择目标目录 → 自动复制数据库、音频与备份，校验成功后写入引导文件并重启；
3. 或点击「仅切换到已有目录」，不复制数据，适合目录中已有旧数据；
4. 点击「恢复默认位置」可回到 `%APPDATA%\大师小说工作台`。

引导文件：`%APPDATA%\大师小说工作台\data-location.json`（记录自定义数据目录，删除即恢复默认）。目标目录不能已存在 `dashi.db`，避免误覆盖。

**数据结构要点**：

- 项目、阶段、章节、正文、版本、大纲、连线、关联、伏笔、音频任务均为独立表；
- 章节正文单独存放于 `chapter_contents`，列表查询不加载正文；
- 章节使用稳定内部 ID（`chp_...`），重命名不影响任何关联；
- 所有写操作在事务中执行，异常退出由 SQLite 回滚；
- 每次保存正文会把上一版归档到 `chapter_versions` 并清理更早版本 —— **只保留当前版本 + 上一个版本**；
- 朗读进度按章保存在项目设置表 `project_settings` 的 `readingProgress` 键（字符偏移 + 百分比）；关闭行为（`closeAction`）与朗读偏好（`rememberReading`、`reading`）保存在 `app_settings` 的 `ui` 键；
- 实时朗读只在内存中合成与播放，**不产生任何音频文件**；只有「离线音频」标签会写入 `audio\<projectId>\` 并占用磁盘。

**环境变量**（调试/便携模式）：

| 变量 | 说明 |
| --- | --- |
| `DASHI_DATA_DIR` | 覆盖数据目录（测试或多实例） |
| `DASHI_PORTABLE=1` | 使用 exe 同级 `data/` 作为数据目录 |
| `DASHI_DEV=1` / `DASHI_DEV_URL` | 开发模式加载 Vite 地址 |

## 六、Agent 接入（本地 API）

### 5.1 获取文档

打开软件左侧底部 **「Agent 接入」**：

- 点击 **「复制完整 Agent 接入文档」** 将完整 Markdown 文档（含真实令牌、服务地址、数据结构、全部接口、调用示例、错误码、安全说明）复制到剪贴板，直接粘贴给外部 AI Agent。
- 「查看完整文档」可预览；「查看 API 定义」查看 OpenAPI 3.1 JSON；「连接测试」验证服务可用性。
- 文档同时以文件形式提供：[docs/AGENT_GUIDE.md](docs/AGENT_GUIDE.md)、[docs/openapi.json](docs/openapi.json)。

### 5.2 连接方式

- 服务只监听 `127.0.0.1`，默认端口 `45871`（被占用时自动顺延）。
- **不要写死端口**：从服务发现文件读取当前地址：
  ```
  %APPDATA%\大师小说工作台\api-endpoint.json
  ```
  其中 `baseUrl` 字段即当前服务地址。
- 鉴权：请求头 `Authorization: Bearer <token>`，令牌在「Agent 接入」页面查看或重新生成。
- 健康检查、版本、OpenAPI、Agent 文档四个端点无需令牌。

### 5.3 快速示例

```bash
BASE=$(node -p "require(process.env.APPDATA + '/大师小说工作台/api-endpoint.json').baseUrl")
TOKEN="<从 Agent 接入页复制的令牌>"

# 健康检查（无需令牌）
curl -s "$BASE/api/v1/health"

# 创建项目
curl -s -X POST "$BASE/api/v1/projects" \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"name":"普法战争","genre":"历史小说"}'

# 创建章节
curl -s -X POST "$BASE/api/v1/projects/<projectId>/chapters" \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"name":"第一章 宣战","stageId":"<stageId>"}'

# 写入正文
curl -s -X PUT "$BASE/api/v1/chapters/<chapterId>/content" \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"content":"一八七〇年七月，巴黎的夏天闷热得反常。"}'

# 创建大纲节点
curl -s -X POST "$BASE/api/v1/projects/<projectId>/outline/nodes" \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"type":"event","title":"色当战役","x":320,"y":180}'

# 建立节点与章节关联
curl -s -X POST "$BASE/api/v1/projects/<projectId>/links" \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"nodeId":"<nodeId>","chapterId":"<chapterId>"}'
```

### 5.4 安全策略

- 默认只允许本机访问，拒绝跨站浏览器请求（Origin / Sec-Fetch-Site 校验）。
- 所有写接口需要 Bearer 令牌；令牌保存在本机数据库，不写入服务发现文件。
- **高危操作默认关闭**：删除项目/阶段/章节、删除节点/伏笔/音频等接口默认返回 `403 FORBIDDEN`，需在「Agent 接入 → 安全与高危操作」中由用户主动开启；开启后仍需请求体 `confirm: true`，删除项目建议附带 `confirmName`。
- 删除阶段必须指定 `chapterAction`（`move` 或 `delete`），不会静默丢弃章节。
- 所有请求记录审计日志（最多 500 条），可在 Agent 接入页查看。

### 5.5 错误处理

| HTTP | 错误码 | 含义 |
| --- | --- | --- |
| 400 | `VALIDATION_ERROR` | 参数校验失败 |
| 401 | `UNAUTHORIZED` | 缺少或错误的令牌 |
| 403 | `FORBIDDEN` | 跨站请求 / 高危操作未开启 |
| 404 | `NOT_FOUND` | 资源不存在 |
| 409 | `CONFLICT` | 版本冲突（乐观锁）或需要确认 |
| 409 | `STAGE_NOT_EMPTY` | 阶段内章节无处可移 |
| 502 | `PROVIDER_ERROR` | 语音服务调用失败 |
| 500 | `INTERNAL_ERROR` | 服务器内部错误 |

错误响应统一为：

```json
{ "error": { "code": "VALIDATION_ERROR", "message": "章节名称不能为空", "details": {} } }
```

## 七、音频与朗读

### 6.1 Windows 本地语音（默认，离线免费）

- 使用系统 SAPI 语音包。若「音频制作」提示未检测到声音，请到
  **Windows 设置 → 时间和语言 → 语音 → 管理语音** 安装中文语音包。
- 本机已验证可用声音：`Microsoft Huihui Desktop`（zh-CN）、`Microsoft Yaoyao`（zh-CN）等。
- **实时朗读**直接把文字交给系统语音在渲染进程里边读边播；**离线音频**的默认语速（-10 ~ 10）在「音频制作 → 服务设置」中调整，两者互不覆盖。

### 6.2 OpenAI 兼容在线语音（可选）

在「音频制作 → 服务设置」填写：

| 配置项 | 说明 |
| --- | --- |
| API 密钥 | 仅保存在本机数据库，不进入文档与日志 |
| 服务地址 | 需兼容 `POST /audio/speech`，可指向自建网关 |
| 模型 | 例如 `gpt-4o-mini-tts` |
| 默认音色 | 例如 `alloy` |

> 使用在线服务会产生费用并受服务商条款约束。生成失败时软件显示具体错误，**不会伪造成功结果**。
> 在线语音只用于「离线音频」标签生成文件；「实时朗读」始终使用系统语音，不联网、不产生费用。

### 6.3 实时朗读（「音频制作」默认页）

打开「音频制作」默认就是 **实时朗读**：点开就能听，边读边播，**不需要事先「生成」，也不落地任何音频文件**。

| 区域 | 能力 |
| --- | --- |
| 提词器窗口（中间） | 当前句高亮居中，上下只显示附近若干句；点击任意一句即从该句开始读 |
| 本章进度条（下半部分） | 可随时左右拖动跳转；拖动时预览目标句，松手立即从该处继续朗读 |
| 章节选择（左下角） | 下拉框按阶段分组，并显示每章已读百分比 |
| 语速（章节选择旁） | **0.1× ~ 3×**（支持两位小数，如 1.35×），点开为滑块与 0.5 / 0.75 / 1 / 1.25 / 1.5 / 2 / 2.5 / 3 预设；朗读过程中修改立即生效，不会从头开始 |
| 声音与音量（右侧） | 选择系统语音、拖动音量 |

- **进度以「字符偏移」记录，每章独立保存**：关闭软件再打开会回到上次听到的位置，并提示「上次读到 X%」，可一键「从头开始」。
- 一章读完后可**自动接着读下一章**。
- 快捷键：**空格** 播放 / 暂停，**Alt + ← / Alt + →** 上一句 / 下一句。
- 同一页面的第二个标签 **「离线音频」** 保留原「生成音频文件」流程（生成 MP3/WAV、播放、导出、任务列表）；两种模式的声音与语速设置互不覆盖。

### 6.4 设置页：关闭与托盘 / 实时朗读

「设置与备份」页新增两张卡片：

| 卡片 | 可设置项 |
| --- | --- |
| 关闭与托盘 | 点击窗口关闭按钮时「收缩到系统托盘（默认）」或「直接退出软件」；托盘右键菜单为「显示主窗口 / 朗读弹窗 / 退出软件」，单击托盘图标恢复窗口；另有「立即收缩到托盘」与「检查托盘状态」按钮 |
| 实时朗读 | 默认语速、音量、音调、默认朗读声音，以及「记住每章听到的位置」「一章读完后自动接着读下一章」两个开关 |

> 选择收缩到托盘后，关闭窗口不会结束进程，实时朗读与离线音频任务会继续运行；需要彻底退出请用托盘菜单的「退出软件」。

### 6.5 朗读迷你弹窗

一个约 **440×600** 的独立小窗口，专门用来「只听不看」地追进度：可以在托盘右键菜单选 **「朗读弹窗」** 打开，也可以从主界面打开。

| 项目 | 说明 |
| --- | --- |
| 窗口形态 | 独立 `BrowserWindow`，有自己的入口页 `mini.html`，尺寸约 440×600，可单独拖动摆放 |
| 不显示正文 | **按设计不显示任何正文文本**，也不显示「读到哪一句话」；只呈现进度与控制，避免小窗占屏 |
| 保留的控制 | 换书（项目）、换章节、换音色、调语速、拖动进度条、播放 / 暂停、上一句 / 下一句、音量 |

| 生命周期 | **关闭主窗口不影响它**（主窗口收缩到托盘时它照常朗读）；**退出软件时随主进程一起关闭** |

## 十、已知限制

- 音频批量生成尚未提供（已预留任务队列与 API 设计，单章生成完整可用）—— 批量生成只针对「离线音频」；「实时朗读」本身就是即时播放，不需要排队生成。
- 「实时朗读」依赖系统的 Web Speech / `speechSynthesis` 能力：若系统未安装语音包或未启用该能力，页面会提示改用「离线音频」生成后播放。
- 实时朗读不写入任何音频文件，因此无法暂停后回放已读过的音频；需要留档或分发的请用「离线音频」。
- 长章节会按短句分段朗读（规避 Windows 本地语音对长文本约 15 秒的截断），段与段之间有极短停顿；进度条上的总时长为按每秒约 4.6 字的估算值。
- 在线语音仅实现 OpenAI 兼容 `/audio/speech` 协议，其他供应商需新增适配器（`electron/main/adapters/tts.ts` 已按接口抽象）。
- 编辑器暂不提供 Markdown 预览与富文本排版，专注纯文本长篇写作。
- 未实现多窗口同时编辑同一章节的实时协同（通过 `baseRevision` 乐观锁避免静默覆盖）。
- **朗读迷你弹窗不显示正文文本**（按设计）：它只做播放与控制，看不到「读到哪一句话」，需要看正文请用主界面的实时朗读提词器。
- **多实例共用同一份程序文件**（同一个 exe / 同一套 `resources`），只有数据是隔离的；因此升级、覆盖安装对所有实例同时生效，不能给不同实例装不同版本。
- **自动排版是启发式算法**：按分层 / 环形 / 分组 / 紧凑规则生成版式并做局部微调，不保证得到全局最优的连线交叉数；节点极多或关系特别稠密时，仍可能需要手动微调。
